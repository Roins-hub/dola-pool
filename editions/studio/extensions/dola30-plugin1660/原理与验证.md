# v1.6.34：Dola 原生模型控制与签名前提交

本轮针对用户截图里Dola缺失2.5的问题。旧版model-selection-main.js的host guard和manifest仅覆盖国内，Dola不绑定模型状态；DOM模型识别又只接受Seedance开头，不接受Dreamina前缀。现在两站共用适配器，保持各自模型范围。

配置恢复发生在原本成功返回的skill pack / action bar配置副本中，早于React消费。仅在已有Dola模型族中缺少seedance_v2.5时补回原生选项，不添加空模型族或其他厂商项，不把国内专用模型复制过去。原有默认ID/索引、选项元数据和权限字段保持；新增ID与现有项不冲突。国内缺失的模型仍不自动补造。

缺失2.5客户端描述时复用用户原插件包的Dola参数描述，来源和恢复项在modelSelection诊断中单列；现有2.5描述不覆盖。它只避免前端读取空的模型参数说明，不代表当前服务器支持、付费权限或任务创建。没有写入新条目的subscription_tag=none等权益标记。

原生菜单选择先写输入store的值及提交记录；只有写入被接受才标记选中。若失败，恢复旧偏好，避免界面未接受却留下隐藏的强制模型。模型值随后进入video-creation参数节点、IM签名前草稿和Dola旧chatMessageService的input_skill.variables；对象及JSON形式、附件、原文、额外参数和原方法返回值保持。分辨率同步支持旧变量的JSON形式。

模型切换不会主动发HTTP；原生提交继续负责序列化和签名。已签名fetch/XHR不改，真实HTTP/业务失败不覆盖，不创建假任务，不自动重试。原生权限节点与提交后节点保留。

233项离线回归通过。新增9项覆盖Dola控制恢复、原生值、Dreamina标签、切回1.0、节点重建、编码变量与错误透传；签名检查是夹具一致性验证，并非平台签名或服务端模型实测。当前浏览器实际跳转地区限制页，线上验证受阻。

国内首轮生成分流仍未解决，保留1.6.33逐字段采集机制继续定位，不将本轮Dola控件修复当作国内直出修复。

## 1.6.33 原生提交控制字段的差分证据

最新一组成功/失败的分组摘要中，只有 option 不同，全部已记录路由值一致。此前只存整组摘要，无法从哈希恢复差异字段，这是已确认的采集缺口；option 的差异也可能来自会话标识，不能凭散列不同指定某个开关为原因。

现在对真实已发送请求的 option/ext/messageExt/clientMeta/userContext、能力对象和输入框镜像逐字段计算SHA-256。对象键排序，JSON编码容器展开，数组保留索引。凭据字段忽略；会话标识和动态元数据分组记录。仅布尔值、有限数值和具名控制枚举保留实际值；未知字符串、原稿及标识均不保留原文。最多256字段、12层、4096步，超过预算或遇到无法安全表示的键/路径会标记覆盖不完整。

最近两次提交的fieldDiff给出变化路径及前后字段摘要，最多展示64个变化并保留总计。覆盖不完整时，未见字段标为not_observed，不能解释为已删除。旧版记录没有fieldDetails时差分保持null，不能从旧散列补算。

另外只读记录原生reply_message_format的长度、摘要、占位符和确认/分镜/视频文字标记，排查回复模板冲突；不依据字段名字猜测用途或擅自改写模板。文字标记不是生成调用证据。

本版生成提交代码与前缀行为沿用上一版。没有修复或声称已修复首轮直接生成，也没有把修复自动续确认当成用户要求的直达流程。下一步需要依据具体字段或实际原生工具调用入口修复，不能复制会话ID或修改响应块编号。

## 1.6.32 已有机制：提交差分与长响应完整分析

## 本轮对照及修复

用户同提示词的成功/失败样本，两次已知视频参数及前缀均真实发出。成功有 1920×1080 资源，而成功响应的任务/扣费候选也为空，说明不能由未识别到字段判断任务失败。两份都不含额度 summary，原始 option/上下文值也没保存；原因尚未确定。

失败页面观察器解析了 1260 个对象，Debugger 却在第 256 个停止。移除该限制后，继续以 2,000,000 字符/已知字节预算限制正文，并对每个事件单独限制结构遍历工作量；所有事件会计数、提取已知结构候选，展示仅保留前 16 和后 16 个事件。结束值 end_type/finish_reason/cmd 等会记录，展示截断不等于正文分析截断。

共享正文读取器新增临时 visitor，供 worker 在内存计算 SHA-256。原稿、输入框镜像、视频参数、完整能力对象和选项/上下文各自形成摘要，导出不包含原文；对象排序稳定化，排除请求/消息标识、时间戳和凭据。会话、分段和机器人标识另外摘要，用于区分上下文；不将随机 ID 长度变化误当作提示词变化。

散列任务不阻塞网页请求，晚到结果只更新仍保留且未中断的对应记录；导出会等待当前散列完成。SHA 不可用时明确记录错误，相等性保持 null。最近两次提交通过 submissionComparison 给出分组相等性、路由值变化和会话标识摘要比较。未知/未完整检查的正文不能被报告为相同。

这一步只补齐定位证据，不改变平台请求，不设置猜测的跳过确认字段，不重放任务，也不把 thinking_block=10040 当视频工具指令。实际执行入口仍需依据真实路由差异定位。

## 本轮确认的错误

1.6.30 用户日志的浏览器请求顶层有 chat_ability，而 `doubao-generation-intent-main.js.inspect` 和 `debugger-summary.js.request` 都只检查消息内 ext。另一个递归传输观察器已读出视频参数，因此不能拿两个 false/null 当作“前缀/视频参数没有发出”的证明。旧文件是摘要，不包含实际消息原文，无法事后恢复丢失值。

新增只读共享模块 `video-request-schema.js`，同时由早期 MAIN 脚本和 worker 导入。它明确区分原生草稿与实际请求：只处理最后一条非系统/助手/工具消息，实际顶层 chat_ability 优先；支持能力对象/JSON、内容块数组/JSON 字符串/Unicode 转义及输入框镜像。输出的是来源、结构、参数和前缀布尔/null，不存原稿、不修改对象。原生签名前前缀写入仍限定已有草稿结构，不向签名后的 body 追加字段。

未知能力或未知正文不再被强制变成 false。页面的 requestIntent 与 Debugger 的 prefixMarkerPresent 保留 null 并显示原因，避免把未知当作缺失。共享模块缺失也保持未知。

用户额度响应只保存了字段路径、没有保存实际布尔/数字，且 schema 前 96 项被 ACK 填满。本版分别增加 quota summary 白名单值、独立的消息/工具路径及逐事件结构；额度数组保留索引以对应具体功能组。结构化错误码/任务/点数仍只是候选，保留 UNVERIFIED。没有新增任何任务接口或平台请求。

## Debugger 改造

旧 worker 的 `activateTab` 只初始化面板，`ensureAttached` 没有调用方，manifest 没有 debugger 权限。新增权限后未复活旧 Fetch 重写实现，而是删除该暂停/返回替换链路，在经典 service worker 中通过 `importScripts` 加载 `debugger-summary.js` 与 `debugger-network.js`。

国内标签页默认 `chrome.debugger.attach(tabId, "1.3")`，成功后 `Network.enable`。只有两步均成功、当前页仍在支持范围且开关未关闭，才报告 attached；attach 失败立即停止，不在失败后调用协议命令，也不把失败显示成 ON。Dola 需要手动启用。重复激活复用连接，待附加操作按标签页合并。

Network 监听当前根标签页目标的 Fetch/XHR/EventSource 请求，不主动附加子 iframe/worker 目标。跨域的这类 API 请求也可出现在该页记录中，以便定位上传和视频工具接口；导出剥离查询字符串。没有调用 Fetch.enable、fulfillRequest、replayXHR、请求拦截或请求头修改命令。不会直接调用网页任务接口。

`requestWillBeSent` 记录已发送消息的真实参数；正文缺失且浏览器提示存在时，调用 `Network.getRequestPostData` 读取。`responseReceived` 和 `dataReceived` 记录真实 HTTP/MIME/字节数；`loadingFinished` 后通过 `Network.getResponseBody` 读取未由页面脚本替换的浏览器响应。来自 service worker 的响应另记 fromServiceWorker。只解码/分析副本，不修改网页响应。

JSON、SSE 和 base64 UTF-8 支持有限结构解析，跳过助手文本中的任务/点数台词；未知结构只保存字段路径。任务 ID 只留存在性、类型和长度，状态码/点数保留数值及原始路径，业务短错误句做凭据/URL 脱敏。候选始终为 UNVERIFIED，不宣称接受任务。

每页最多 60 条摘要，优先淘汰其他请求、保留最近提交；历史接口与提交明确分类。前台有停止、清空、导出按钮。清空、停止或关闭页后，晚到的异步正文不能重新填回旧记录。断开事件尊重用户/DevTools 决定，不自动抢占；需手动重新启用。导航离开支持范围会停止采集、尝试分离，失败明确报告。

通过 storage.session 缓存摘要、开关和浏览器请求关联。后台重新执行时，若保存的会话显示此前拥有连接，先用当前扩展的 Network.enable 核实所有权，成功才报告恢复，失败后才重新尝试 attach。不会凭“目标已有调试器”推定自己拥有连接。会话记录无法跨扩展重载或浏览器重启保留。

本版不增加虚假的生成结果；目的是给下一次失败提供实际协议证据，不能把开启 debugger 当成直接生成已修复。

## 问题与改动

1.6.28 只在第一轮回复后尝试一次原生续确认，没有首次提交前缀；不能保证第一轮直接调用视频工具。用户截图又把包含“生成参数确认”的稿件作为输入，这会触发自动续确认模块原有的归属保护。现在该暂停有明确诊断原因，前缀独立处理这类视频输入。

旧 `doubao-direct-generation-main.js` 在 1.6.26 已删除，仍不加载。新 `doubao-generation-intent-main.js` 不要求助手伪称合法权限、受理或成功，而是明确请求实际调用；无权限、额度或工具错误时要求如实说明。指令本身不能替代真实调用或授予账号权益。

## 原生签名前链路

新模块仅安装在国内 MAIN 环境，在 `resolution-native-main.js` 已有原生 IM `sendMessage` 钩子中调用：

1. 清理可确认是网页额外加入的时长后缀；
2. 执行原有时间轴转换、模型及分辨率参数处理；
3. 对当前视频消息加入生成指令前缀；
4. 原有自动续确认观察器记录本轮提交；
5. 同一次原生 `sendMessage` 继续构造、序列化、签名并发送。

原生方法的 this、额外参数、返回值保持。新模块没有 fetch/XHR 发送代码，没有重放或第二次生成请求，不在签名后改正文或 URL。未知结构或模块异常不阻断原生提交。

只处理 `messages` 最后一条明确含 `chat_ability.ability_type=17` 的非助手/系统/工具消息，不向后搜索历史。只编辑已知正文路径、第一段非空文本块及原生 `input_box_content.user_input_content`；各类镜像字段保持一致，多个文本块不会逐块加指令。对象/JSON 字符串表示形式保留，附件块及其他元数据不变。完整前缀已存在时不重复加入。普通聊天不自动提升为视频能力。

前缀不删除用户复制的参数稿，也不删除用户自己的“生成视频：”标签。原稿后缀和时间轴处理沿用前版行为，新增前缀不改写其后的剧情或素材引用。

## 两个观察点

`generationIntent.last` 及 `bridge.lastDraft.intentPrefixAdded` 记录原生应用对象处理。`resolution-main.js` 的原有只读传输观察器另外解析交给 fetch/XHR 的 JSON 正文，调用新模块的纯读取 `inspect`，把结果记入 `generationEvidence.requestIntent`。该观察不改请求，不产生网络操作；前缀开关关闭时也可以如实观察用户自己带入的完整前缀。

`requestIntent` 仅有 video/present/inputBoxPresent 布尔值，不存剧本、链接、素材名或账号标识。只能证明在可读取的出站正文里存在前缀，不能证明服务端已经收到或创建任务。读不到正文时保持 null。

响应诊断不从助手文本中提取任务或点数，仍保留 `verification=UNVERIFIED`。自动确认动作和前缀发送均不被报告为视频任务成功。最近一次响应的序号与页面导航保留机制沿用 1.6.27。

## 自动续确认及 Dola

自动续确认仍要求新鲜可信手动视频提交、已结束的本轮响应、新确认结构、匹配参数和真实原生控件，每轮最多动作一次。原稿含确认标题时不启动该自动动作，现在显示 `skipped_prompt_confirmation`；不影响生成前缀。原生控件和编辑器操作的其他停止条件沿用 1.6.28。

Dola 不安装新前缀或国内自动续确认模块。原插件的 Dola 配置、素材和原生提交代码没有提供可复用于国内的已验证免确认字段，不猜造 `skip_confirm` 或权限值。
