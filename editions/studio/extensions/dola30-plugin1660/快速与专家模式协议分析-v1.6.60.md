# 快速模式与专家模式协议分析（v1.6.60）

分析输入：`download.json`（只比较请求结构，不记录 Cookie、签名、提示词正文或会话 ID）。

## 已确认差异

| 项目 | 快速模式提交 | 专家模式提交 |
|---|---|---|
| HTTP 入口 | `/chat/completion` | `/chat/completion` |
| `option.agent_mode` | `2` | `1` |
| `option.need_deep_think` | `0` | `4` |
| `model_item_key` | 快速路由值 | `4` |
| 浏览器请求中的视频模型/时长 | 未暴露 | 未暴露；由专家 Agent 在服务端调用工具 |
| `is_audio` / `tts_switch` | `false` / `false` | `false` / `false` |

结论：两种模式虽然都提交到 `/chat/completion`，但服务端路由不同。快速模式的浏览器请求没有一个可直接改成“Seedance 2.0 Fast、15 秒”的稳定字段；专家模式的 Fast 15 秒和声音来自服务端 Agent 选择的视频工具，不是客户端 `is_audio` 或 `tts_switch` 开关。

## v1.6.60 的处理

- **专家模式协议**：沿用已验证的专家 Agent 转换，写入 `agent_mode=1`、`need_deep_think=4`、`model_item_key=4`，并保留提示词、原生图片附件、批量发送和左侧新会话验收。
- **快速模式协议**：保持 `agent_mode=2`，不加专家提示词、不删除快速路由。当请求原本包含 `ability_type=17` 的直接视频能力时，将现有参数写成用户所选模型、秒数、画幅和分辨率；如果请求没有暴露该能力，保持原请求，不伪造 `chat_ability`。

## 能力边界

快速模式是否真正按 Fast 15 秒生成、消耗哪种额度以及是否带声音，最终由 Dola 服务端授权和能力表决定。客户端强行伪造能力字段可能被服务端拒绝、降级到支持时长，或切换到直接视频额度，因此扩展只报告真实 HTTP 和会话证据，不把被降级的结果标成 Fast 15 秒成功。

## 验证方法

1. 重新加载 v1.6.60 扩展并刷新 Dola 页面。
2. 选择 `Seedance 2.0 Fast / 15 秒 / 画幅 / 分辨率`。
3. 点击“快速模式协议”。
4. 导出调试，核对本次请求仍为 `agent_mode=2`；若请求存在视频能力字段，应看到对应参数变化。
5. 以左侧新增会话和最终视频卡片的实际时长为成功依据，不能只看扩展状态文字。
